Attention Is a Lookup That Keeps Everything

Start with a Python dict. You hand it a key, it finds the exact match, and it gives you back the value. Attention is the same lookup, made soft. The keys and values are vectors, and the query q need not match a key exactly. Every stored key k gets a score for how well it matches q: the dot product q·k. For unit-length vectors that score is the cosine of the angle between them. It is 1 when they point the same way, 0 when they are perpendicular, and negative when they point apart. Softmax turns the scores into weights that are positive and sum to 1, and the output is the weighted blend of all the values.

Every token makes its own query, key and value by multiplying its embedding by three learned matrices, Wq, Wk and Wv. The query is "what am I looking for", the key is "what do I offer", and the value is "what I hand over if you pick me".

Four cached tokens, each with a unit-length 2-D key (orange). Turn the query (blue): a key pointing away from it scores below zero and gets a small weight. The weights here are softmax(3 q·k), so the toy keys show a clear preference.

Now generation. To produce token 1,001, the newest token's query gets compared against the keys of all 1,000 earlier tokens. The model stores those keys and values instead of recomputing them: the KV cache. Every new token adds one more key and value, per layer and per head, so memory and the work per new token both grow with the length of the text. At a million tokens, that list is the bottleneck.

Drop the Softmax and You Get an RNN

Store one key-value pair as a matrix:

S = k vT

S is dk × dv. To look up a value, read it with a query:

STq = (k vT)Tq = v (kTq)

Set q = k, a dict-style lookup of an existing key, with k and v unit length, and you get the value back:

STk = v (kTk) = v ‖k‖2 = v

Now write attention as a weighted sum, with the softmax scores as the weights:

o = Σi softmax(q·ki) vi

Delete the softmax and use the raw scores as the weights. The query is the same in every term, so it comes out of the sum:

o = Σi (q·ki) vi = (Σi vi kiT) q = STq,  S = Σi ki viT

That is exactly the lookup from before. Because S is a running sum, there's no need to keep a list at all. Each new token adds its (k, v) pair, and you throw the token away:

St = St−1 + kt vtT,  ot = StTqt

That's a hidden state, an update that folds in the new input, and a readout. In other words, an RNN, with a matrix for a state instead of a vector.

You can't do this with the softmax in place. The weight is exp(q·k) divided by a sum over every key, and that doesn't split into a part that depends on q multiplied by a part that depends on k. Removing the softmax is what makes the regrouping possible.

Each new token adds one key and value to the cache. The state S stays one dk × dv matrix, whatever the length.

The payoff is memory. With 128-dimensional keys and values, the KV cache adds 256 numbers per token per head, which is 25.6 million numbers at 100k tokens. The matrix state is 128 × 128 = 16,384 numbers per head, whatever the length. In bf16 (2 bytes), a 100k context shrinks from 51 MB to 33 kB per head, roughly 1,500 times smaller.

The Running Sum Has a Bug

Read the matrix with a stored, unit-length key and you get its value. Now write the same pair again. Every write adds, so you read back 2v. Write it n times and you get n·v. When you do dict[key] = value twice in code, you expect {key: value}, not {key: 2*value}. The running sum never replaces anything: a new value for an old key reads back as "old plus new".

It gets worse once keys overlap. A matrix holds pairs cleanly only if their keys are perpendicular, and 128-dimensional keys only have 128 perpendicular directions, so 128 clean pairs at most. Past that, every read picks up a bit of the other values, in proportion to how similar their keys are. This is crosstalk. Softmax keeps every pair in its own slot, so nothing collides. Crosstalk is the price of a fixed-size matrix.

Two pairs in one matrix. Reading with k1 returns v1 plus (k1·k2) times v2, so the more k2 leans toward k1, the more of v2 leaks in (blue). Past 90° the dot product is negative and v2 is subtracted instead.

The Delta Rule: Read What's Stored, Write the Difference

Look before you write. Read what the memory currently holds at this key, STk, and write only the difference between that and the new value:

S ← S + β k (v − STk)T

With β = 1 and a unit-length key, reading afterwards gives exactly v. Write the same pair twice and the difference is zero, so the second write does nothing. The "delta" in DeltaNet is that difference, v − STk, which is an error term when the standard is "look up k, get v exactly".

Give the memory a tiny objective for this one token: make STk equal v. The loss is plain least squares, and its gradient points along the key, scaled by the error:

L = ½ ‖STk − v‖2,  ∇SL = k (STk − v)T

Take one gradient step with the write strength β as the learning rate, and each token's (kt, vt) pair is written this way:

St = St−1 − βt ∇SL = St−1 + βt kt (vt − St−1Tkt)T

That is the delta rule again, so each token is one gradient-descent step on the state S. The trained W matrices never change during inference, but they make every token's k, v and β, so they set what gets written and how strongly. The current S matters too, because the update only stores the error v − STk. S starts at zero for each sequence, so the first write of a pair goes in full. If the same pair shows up later, the write is only a correction. That's why the papers call S "fast weights" (the W matrices are the fixed, slow ones) and talk about "test-time training".

β is between 0 and 1, and the model makes it fresh for every token from that token's embedding, like q, k and v. It's a write strength: β = 1 overwrites, β = 0.1 nudges the stored value 10% of the way.

Bars show the read error ‖STk − v2‖, with k, v1 and v2 unit length and v1, v2 perpendicular. The scale ends at 10.

k already holds v1. Each click writes v2 to it in both memories. The plain sum's read drifts to v1 + n·v2, while the delta rule shrinks its error by a factor of (1 − β) every write and lands on v2.

The papers print the same rule grouped by S:

St = (I − βt kt ktT) St−1 + βt kt vtT

The first part erases state built up previously: it shrinks whatever is stored along k by a fraction β and leaves everything perpendicular alone. The second part writes the new value at k. Together, the two parts make the read at k a moving average: (1 − β) of the old value plus β of the new one. One β controls both, which matters later.

What's Next

The delta rule only forgets along keys that get rewritten. Gated DeltaNet adds a forget gate that shrinks the whole state a little at every step, much like an LSTM's forget gate. Kimi Linear makes that decay per channel, and Gated DeltaNet-2 gives erasing and writing their own knobs. Part two covers them.
