Companion to the DeltaNet post

How attention became an RNN again

Four steps from softmax attention to DeltaNet, each with a figure you can play with. Code: deltanet.py in this repo.

1 · Attention is a soft lookup over a list that keeps growing

Start with a Python dictionary. You hand it a query. It finds the key that matches exactly and gives back that key's value. Attention is the same lookup, made soft. Every stored key scores how well it matches the query, and that score is the dot product q·k, which is large when the two vectors point the same way. Softmax turns the scores into weights that are positive and sum to 1. The output is the weighted blend of all the values. A key that matches strongly contributes most of its value, and a weak match contributes almost nothing.

In a language model, every token produces its own query, key and value, each from its embedding times a learned matrix (Wq, Wk, Wv). Read them as: the query is "what am I looking for?", the key is "what do I offer, as an advert?", and the value is "what I hand over if you pick me". Keys and values are separate because what makes a token easy to find need not be what it should pass along.

Try it: four earlier tokens, each with a 2-D key (the coloured arrows) and a value (its colour). Turn the query and watch the weights and the blended output change.

Now generation. Modern LLMs are decoder-only: there is no separate encoder, just one stack where each token can look only at itself and earlier tokens. To produce token 1,001, the newest token makes a query and looks it up against the keys of all 1,000 earlier tokens. Those keys and values never change once computed, so the model stores them instead of recomputing them. That store is the KV cache. Each new token adds one more key and value to it and has to compare its query against everything already there. Memory therefore grows linearly with the length of the text, and so does the work per new token. At a million tokens of context, that list is the bottleneck.

Example: "What does the fox say"

"What" can only look at itself, "does" looks at "What" and itself, and so on. Each row of the grid below is one token's query, and the filled cells are the keys it's allowed to see. That's the triangle, which the papers call the causal mask (the M or Tril in Kimi's notation section).

The five prompt tokens are not processed one after another. It is still exactly softmax(q kᵀ) v for every token. The only change is that all five lookups are stacked into matrices and done in one go. That pass is called prefill:

  1. Stack the five token embeddings as rows: X is 5 × d.
  2. Q = X Wq, K = X Wk, V = X Wv. Each is 5 × d, one row per token, and all three are computed at once.
  3. Q Kᵀ is 5 × 5. Entry (i, j) is qᵢ·kⱼ, token i's query scored against token j's key. This is the grid above.
  4. Set the cells above the diagonal to −∞, so softmax turns them into weight 0. That's the mask. Then apply softmax to each row on its own, which gives each token its own weights summing to 1.
  5. Multiply by V to get a 5 × d result. Row i is token i's blended output, exactly what you'd get by running the one-query lookup for token i by itself.

So prefill is five separate lookups written as one matrix multiply, which a GPU does in one shot. That's the parallelism that made transformers win over RNNs. Generation is the part that has to be sequential. The output at "say" predicts the next token, say "ring". Then "ring" gets one new query, a single row: q is 1 × d against K, now 6 × d, giving 1 × 6 scores. That's the highlighted bottom row. The five earlier keys and values already sit in the KV cache, so they are reused rather than recomputed. (Every layer has its own attention, so every layer keeps its own cache.)

2 · A single matrix can store key→value pairs

S = k vᵀ is a dk × dv matrix. What matters is what it does. Read it with the key it was built from:

Sᵀ k = (v kᵀ) k = v (kᵀ k) = v · ‖k‖²

The only move is regrouping the brackets, which matrix multiplication always allows. The middle part, kᵀk, is a plain number: the key's squared length. For a unit-length key it is 1, so you get v back exactly. Read it with a perpendicular key k′ and the middle number is kᵀk′ = 0, so you get nothing back. The matrix behaves like a one-entry dictionary: ask with the right key and you get the value, ask with an unrelated key and you get silence.

Now add a second pair into the same matrix: S = k₁v₁ᵀ + k₂v₂ᵀ. Reading with k₁ gives v₁(k₁·k₁) + v₂(k₂·k₁). If the keys are perpendicular, the second term vanishes and you get exactly v₁. One fixed-size matrix holds many pairs layered on top of each other, with no slots and no list. The catch is that only dk directions can be mutually perpendicular. Past that, keys must overlap, and every read picks up crosstalk from the others, in proportion to how similar their keys are.

The derivation, one rule per line

S = k₁v₁ᵀ + k₂v₂ᵀthe two stored pairs
Sᵀ = v₁k₁ᵀ + v₂k₂ᵀthe transpose of a sum is the sum of the transposes, and (a bᵀ)ᵀ = b aᵀ
Sᵀk₁ = v₁k₁ᵀk₁ + v₂k₂ᵀk₁multiply both terms by k₁ (distributivity)
= v₁(k₁ᵀk₁) + v₂(k₂ᵀk₁)regroup the brackets (associativity). Each bracket is (1×d)(d×1) = 1×1, so it's a plain number
= v₁(k₁·k₁) + v₂(k₂·k₁)a row vector times a column vector is just the dot product

With numbers. Take k₁ = (1, 0), k₂ = (0, 1), v₁ = (3, 5), v₂ = (7, 2).

S = [[3,5],[0,0]] + [[0,0],[7,2]] = [[3,5],[7,2]]

Reading with k₁: Sᵀk₁ = 1·(3,5) + 0·(7,2) = (3,5) = v₁ ✓. When the keys are the axis directions, the rows of S are literally the stored values, so it's an ordinary lookup table. Tilt the keys away from the axes and every row holds a mixture of the values. A read still untangles them, as long as the keys stay perpendicular. That's what the demo below lets you break.

3 · Remove the softmax and the growing list becomes one matrix

Write step 1's attention as a sum. The output for query q is o = Σᵢ wᵢ vᵢ, where the weights wᵢ are the softmax of the scores q·kᵢ. Now do the one thing linear attention does: delete the softmax and use the raw scores as weights. Then the same bracket-regrouping from step 2 finishes the job:

o = Σᵢ (kᵢ·q) vᵢraw scores as weights
= Σᵢ vᵢ (kᵢᵀ q)a number times a vector can sit on either side
= (Σᵢ vᵢ kᵢᵀ) qregroup: q is the same in every term, so pull it out of the sum
= Sᵀ q, with S = Σᵢ kᵢ vᵢᵀwhich is exactly step 2's matrix, holding every earlier pair

So "look up q against the whole list" and "read one matrix with q" are the same computation. And because S is just a running sum, there's no need to keep the list at all. Each new token adds its own pair, and you throw the token away:

St = St−1 + kt vtᵀ, ot = Stᵀ qt

Look at the shape of that. There's a hidden state, an update rule that folds in the new input, and a readout. That's an RNN, the familiar ht = f(ht−1, xt). The only difference is that the state is a matrix instead of a vector. This is the very first equation in Kimi Linear's background section (§2.2). Everything after it in both papers is an edit to how St−1 becomes St.

Why couldn't you do this with the softmax in place? Softmax weights are exp(q·kᵢ) divided by the sum over every key. The exp doesn't split into "a part depending on q" times "a part depending on kᵢ", so q can't be pulled out of the sum. Removing the softmax is what makes the regrouping legal. The price is what step 2 showed: no averaging, nothing ever replaced, and a fixed capacity. The model also still trains in parallel: drop the softmax from step 1's masked QKᵀ · V and it computes the same outputs. It's one formula with two ways to run it. The papers call these the parallel (or chunkwise) form and the recurrent form.

4 · The delta rule: read before you write

The flaw in St = St−1 + k vᵀ is the one from step 2: it can only add. Writing the same pair 50 times gives 50v, and writing a new value for an old key gives "old + new". What you actually want is a write that guarantees reading with k afterwards returns v.

The fix is to look first. Read what the memory currently holds at this key, vold = Sᵀk. Then write only the difference:

S ← S + k (v − Sᵀk)ᵀ

Check it with step 2's reading rule. The new read is vold + (v − vold)(kᵀk) = v for a unit key. So the old value is replaced, not added to. Write the same pair a second time and the difference is zero, so nothing changes. Other keys are untouched, as far as they're perpendicular to k. Then add one knob: a write strength β ∈ [0, 1], produced fresh for each token from that token's own embedding, like q, k and v.

St = St−1 + βt kt (vt − St−1ᵀ kt)ᵀ

β = 1 overwrites completely. β = 0.1 nudges the stored value 10% of the way toward the new one. This is DeltaNet, and "delta" is the difference v − Sᵀk, the error.

Try it. Key k already stores orange. Each click writes "k → blue" into both memories. The plain sum keeps piling on, while the delta rule settles.

"Size" is ‖Sᵀk‖ divided by ‖blue‖. The goal is 1.0, the right colour at the right size.

Why the papers call this "online gradient descent"

Set the memory a task for this one token: make Sᵀk equal v. The loss is L = ½‖Sᵀk − v‖². It's ordinary least squares, the same shape as ½‖Wx − y‖², where the gradient is famously error times input, (Wx − y) xᵀ. The chain rule gives exactly that: the outer ½ and square give the error, and the inner Wx gives the x. Here the "input" is k and the error is Sᵀk − v, so ∇SL = k (Sᵀk − v)ᵀ. One step downhill with learning rate β:

S − β k (Sᵀk − v)ᵀ = S + β k (v − Sᵀk)ᵀ

That's the delta rule, character for character. So each token runs one step of gradient descent on the memory, at inference time, inside the forward pass. This is where the papers' vocabulary comes from. S is the "fast weights", trained per token, while the W matrices are the slow weights, trained once. You'll also see "online learning" and "test-time training". And β is literally a learning rate that the model picks per token.

The form the papers print

Multiply out the brackets and group the terms by S, and you get the version in Kimi's eq. (1) and GDN-2's eq. (7):

St = (I − βt kt ktᵀ) St−1 + βt kt vtᵀ

Read it in two parts. (I − βkkᵀ) erases: it shrinks whatever is stored along the k direction by a fraction β and leaves everything perpendicular alone. βkvᵀ then writes the new value at k. Notice that the same β sets both how hard to erase and how hard to write. Hold onto that observation, because Gated DeltaNet-2 is built on it.
